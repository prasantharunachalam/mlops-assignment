KEY FLOWS:

┌─────────────────────────────────────────────────────────────────────────┐
│                       MODEL LIFECYCLE FLOW                              │
└─────────────────────────────────────────────────────────────────────────┘

DRAFT → VALIDATED → APPROVED → STAGING → PRODUCTION → ARCHIVED
  ↓         ↓          ↓           ↓          ↓
  └─────────┴──────────┴───────────┴──────────┘
          (Rollback transitions allowed)


┌─────────────────────────────────────────────────────────────────────────┐
│                      DEPLOYMENT WORKFLOW                                │
└─────────────────────────────────────────────────────────────────────────┘

1. User creates deployment → REQUESTED status
2. Worker picks up → VALIDATING (checks approval gates)
3. Worker deploys → DEPLOYING (simulated 5s delay)
4. Outcome:
   - Success → SUCCEEDED
   - Failure → FAILED (can retry up to 3 times)
5. Rollback: Creates new deployment to previous version


┌─────────────────────────────────────────────────────────────────────────┐
│                    CONCURRENCY CONTROLS                                 │
└─────────────────────────────────────────────────────────────────────────┘

1. Optimistic Locking:
   - ModelVersion has row_version field
   - Lifecycle promotion requires current row_version
   - Stale version triggers 409 Conflict

2. Idempotency:
   - Each deployment has unique idempotency_key (UUID)
   - Duplicate key triggers 409 Conflict
   - Retry preserves original key

3. Worker Concurrency:
   - SELECT ... FOR UPDATE SKIP LOCKED
   - Multiple workers can run safely
   - No deployment processed twice


┌─────────────────────────────────────────────────────────────────────────┐
│                      TECHNOLOGY STACK                                   │
└─────────────────────────────────────────────────────────────────────────┘

Frontend:  Angular 17 (Standalone) + Material Design + RxJS
Backend:   FastAPI + SQLAlchemy + Pydantic + Alembic
Database:  PostgreSQL 16 (JSONB support)
Worker:    In-process poller (background thread)
Container: Docker Compose (db + backend + frontend)
Testing:   pytest (backend), Jasmine/Karma (frontend)


┌─────────────────────────────────────────────────────────────────────────┐
│                        SECURITY NOTES                                   │
└─────────────────────────────────────────────────────────────────────────┘

- No authentication (future: JWT + role claims)
- Pydantic validation on all inputs
- SQLAlchemy ORM (prevents SQL injection)
- Environment variables for secrets
- CORS configured for frontend origin
